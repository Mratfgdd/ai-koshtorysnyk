## 1. Структура кошторису

16 секцій у фіксованому порядку. Секція показується лише коли в ній є позиції
з кількістю більше нуля — у шаблоні це `=IF(sum(D22:D44)>0,1,0)` у колонці `A`.

```
prep             Підготовчий етап          рядки 20–66
water_supply     Водопостачання            68–119
irrigation       Автоматичний полив        121–238   (+ насосна станція 191–214)
lighting         Освітлення                240–350
drainage_storm   Водовідведення            352–453
drainage_ground  Дренаж                    455–497
paving           Бруківка                  499–575
pathway          Доріжка                   577–628
geogrid          Георешітка                630–662
planting         Озеленення                664–765   (+ блок «Рослини» 666–716)
lawn             Газон                     767–809
planters         Кашпо                     811–853
concrete         Бетонні роботи            855–908
fire_zone        Зона вогню                910–941
extra_works      Додаткові роботи          943–988
summary          Рахунок загальний         990–1035
```

Кожна секція = блок **Матеріали** + блок **Робота** + `Разом за матеріали` +
`Разом за роботу` + `Разом <Секція>`. Секція `Озеленення` має додатковий блок
**Рослини** з окремим підсумком `Разом за рослини`.

Підтвердження: у п'яти наданих КП набір секцій різний — Будьків має 4 секції,
Ромашка 15, Пимоненка 2. Порядок скрізь однаковий.

## 2. Підсумкові формули

Взято з рядків 1008–1035 аркуша `Шаблон основний!!!! 1`:

| Показник | Формула в шаблоні | Клітинка |
|---|---|---|
| Разом за матеріали | `SUM(F992:G1007)` | `G1008` |
| Разом за роботу | `SUM(F1011:G1025)` | `G1026` |
| Загальний рахунок | `IF(F1028=TRUE,(G1008+G1026)*(G1028+100%),G1008+G1026)` | `G1031` |
| Аванс (матеріали) | `=G1008` — 100% вартості матеріалів | `G1033` |
| Аванс (роботи) | `CEILING.MATH(G1026*0.3,100)` | `G1034` |
| Залишок | `G1031-G1033-G1034` | `G1035` |

Надбавка за безготівковий розрахунок: **6%** (`G1028 = 0.06`), вмикається
прапорцем `F1028`.

### Перевірка на реальному КП «Галина Будьків»

```
матеріали           456 969,00
роботи              284 591,00
Загальний рахунок   741 560,00   = 456 969 + 284 591          ✓
Аванс (матеріали)   456 969,00   = 100% матеріалів            ✓
Аванс (роботи)       85 400,00   = ОКРВГОРУ(284 591×0,3; 100) ✓
Залишок             199 191,00   = 741 560 − 456 969 − 85 400 ✓
```

Ці числа закріплені тестом `tests/test_totals.py`.

> **Важливо.** У шаблоні **немає** правила «роботи = N% від матеріалів».
> Роботи — це окремі позиції каталогу з власними цінами, а їх кількості
> обчислюються від матеріалів та драйверів.

### 3.6 Доставка сипучих матеріалів (рядки 536–538)

Для кожного сипучого матеріалу окремо, за обсягом у м³:

```
повних рейсів MAN (15 м³) = ЦІЛЕ(обсяг / 15)
залишок = обсяг mod 15
  0 < залишок ≤ 5   -> +1 ЗІЛ   (до 5 м³)
  5 < залишок ≤ 10  -> +1 КАМАЗ (до 10 м³)
     залишок > 10   -> +1 MAN   (до 15 м³)
```

```
площа > 400        -> кратно 400 великими, залишок малими
```

### 3.9 Транспорт і невраховані витрати

Це **не відсоток**, а прапорці наявності на рівні секції:

```
Транспортні витрати            = 1, якщо в секції є хоч один матеріал
Логістика та постачання        = 1, якщо в секції є хоч один матеріал
Витратні матеріали             = 1, якщо в секції є хоч один матеріал
Доставка спецтехніки (Bobcat)  = 1, якщо орендували спецтехніку
Доставка плит (гідроборт)      = 1, якщо є плити
Доставка рослин (маніпулятор)  = 1, якщо є рослини
```

### 3.10 Кашпо: атрибути позиції

Колонки `L`, `M`, `N` бази — це властивості конкретного кашпо:
`обєм кашпо` (л), `агрік для кашпо` (м²), `геотекстиль для кашпо` (м²).
Наприклад Zelenobox S куб 40×40×40 → 64 л / 0,16 м² / 0,8 м².

```
Загальний обєм кашпо = Σ (кількість × обєм)
Агрополотно          = Σ (кількість × агрік) × 1,2
Геотекстиль          = Σ (кількість × геотекстиль) × 1,2
```

### 3.11 Підбір бруківки за назвою

Рядки 544–554 використовують `SUMIFS` з масками по назві:

```
Монтаж бруківки 6см (тротуарна плитка)  = Σ позицій "*Бруківка*" + "*6см*" + "*тротуарна плитка*"
Установка поребриків 25см               = Σ позицій "*Поребрик*" + "*250*"
Зарізка поребриків                      = поребрики × 0,25
Зарізка бордюрів                        = бордюри × 0,15
Європалета                              = бруківка 6см/9,5 + 8см/7 + 10см/6 + поребрик 6см/38 + …
```

## 5. Ціноутворення й нормалізація товарів

Шаблон бере ціну точним `VLOOKUP` за назвою:

```
E: =IFNA(VLOOKUP(C22,'2026 База 1'!B:C,2,0),"")   одиниця виміру
M: =IFNA(VLOOKUP(C22,'2026 База 1'!B:E,4,0),"")   ціна реалізації
L: =IFNA(VLOOKUP(C22,'2026 База 1'!$B:$D,3,0),"") собівартість
```

Тому **назва позиції має точно збігатися з базою**. Система нормалізує пробіли,
регістр і апострофи з обох боків, а якщо точного збігу немає — шукає кандидатів
за категорією, ключовими словами, характеристиками (діаметр, розмір, щільність)
і одиницею виміру. Якщо впевненого переможця немає — **питає**, а не вгадує.

Класифікація рядків бази на матеріал / роботу / рослину: за одиницею виміру
(`послуга`, `год`, `день`, `поверх` — завжди робота), за категорією
(`Рослини` — рослина) і за початком назви (`Монтаж`, `Демонтаж`, `Укладання`…).

### 5.1. Остання продана ціна

Рішення замовника: **позиція коштує стільки, за скільки її продали востаннє.**
База дає прайс, видані КП дають факт продажу; де є факт — він і застосовується.

Це не теоретичне правило, його диктують самі дані (`scripts/learn_references.py`
на 14 виданих КП):

| Що | Скільки |
|---|---|
| артикулів у 14 виданих КП | 555 |
| з них продано більш ніж за однією ціною | 96 |
| артикулів, спільних із базою | 300 |
| з них база збігається з останньою проданою | 243 |
| з них база відрізняється | 13 |
| у базі без ціни — ціну дає лише історія | 44 |
| продавалось, але в базі немає зовсім | 270 |

Найголовніше: **жодна з 202 рослин у базі не має ціни**, а 14 КП містять
165 різних рослин. Без історії озеленення не порахувати взагалі.

**Як обирається ціна.** Дата видачі КП береться з назви файлу: явна
(`… 15.06.2026`) або квартал (`КП 2026 (1 Квартал) …`) — у самому документі
поле «Дата рахунку» порожнє, а метаданих PDF не має. Береться ціна з
найновішого КП, у якому ця позиція є. Якщо кілька КП одного кварталу
розійшлися в ціні, береться та, яку застосувала більшість із них; решта цін
записується в пояснення до рядка, щоб кошторисник бачив, що саме відкинуто.
КП без дати в назві вважається найстарішим. Середнє не рахується ніколи:
середня ціна — це ціна, за якою ніхто нічого не продавав.

Собівартість завжди лишається з бази: КП фіксує, скільки взяли з клієнта, а не
скільки це коштувало компанії.

Якщо ціни немає ні в базі, ні в історії — позиція стає питанням
(`NEEDS_USER_INPUT`), як і раніше.

**Що це дає.** Кошторис Будьківа, зібраний із креслень і оцінений без власного
КП цього об'єкта в історії:

| Джерело цін | Підсумок | Підписане КП | Сума розбіжностей по блоках |
|---|---|---|---|
| лише «2026 База 1» | 487 204,00 | 741 560,00 (65,7 %) | 263 936,00 |
| остання продана ціна | 741 013,00 | 741 560,00 (99,9 %) | 115 893,00 |

Підсумок сходиться до 547 грн частково тому, що відхилення блоків
різнонаправлені й гасять одне одного — тому в таблиці стоїть і сума модулів
розбіжностей. Перевіряти: `python scripts/compare_reference.py --root <тека>`.

## 6. Перевірки, взяті з шаблону

Колонка `N` шаблону містить власне правило контролю:

```
=ifs(K22=0,"ВНЕСИ СОБІВАРТІСТЬ 1 од", K22<=G22,"ОК", K22>G22,"ПОМИЛКА")
```

Реалізовано як:

* собівартість > ціни реалізації → **ERROR** «Собівартість вища за ціну»;
* собівартість не внесена → **WARNING** «Не внесено собівартість».

## 7. Виявлені проблеми у вихідних даних

Знайдено при імпорті; **не виправлено автоматично** — потребує вашого рішення.

1. **Дві позиції з однаковою назвою і різною ціною:**
   * `Світлодіодна стрічка Rishang 2835-120-IP67-G-10-24 RD30C0TC-A` — 355 і 450 грн;
   * `Зворотня засипка траншеї` — 45 і 80 грн.

   `VLOOKUP` у шаблоні бере **перше** входження, тож зараз мовчки застосовується
   355 і 45. Система це фіксує як конфлікт.

2. **274 позиції без ціни реалізації**, з них **усі 202 рослини**. Асортимент
   рослин ведеться без цін — вони визначаються за прайсом розсадника на
   конкретний проєкт. Тепер ціну для них дає історія виданих КП (розділ 5.1);
   там, де рослину ще жодного разу не продавали, система не підставляє нуль
   мовчки, а ставить питання «Яка ціна за 1 шт?».

3. **Категорія «Паркан» — 16 порожніх рядків**: заповнені одиниці виміру, але
   немає ні назв, ні цін. Пропущено при імпорті.

4. **Ручні коригування в КП Будьків.** Формула дає `Грунт родючий = 21 м³`
   (259 × 0,08) і `Пісок = 5 м³` (259 × 0,02), у виставленому КП стоїть 20 і 10.
   Це нормальне рішення кошторисника — система дозволяє перекрити будь-яку
   кількість, позначає її як `user_input` і перераховує залежні позиції.

## 8. Як оновити правила після зміни шаблону

```bash
python scripts/compile_template.py  "шлях/до/Шаблон для ШІ.xlsx"
python scripts/import_catalog.py    "шлях/до/Шаблон для ШІ.xlsx"
python scripts/import_references.py "шлях/до/теки з проєктами"
```
