2. ЩО AI МАЄ НАВЧИТИСЯ РОБИТИ
==================================================

AI повинен вивчити закономірності з готових кошторисів.

НЕ потрібно просто копіювати старі кошториси.

Потрібно витягнути з них правила:

- структуру кошторису;
- категорії;
- типи робіт;
- типи матеріалів;
- залежності між об'єктом і необхідними товарами;
- кількість товарів;
- одиниці вимірювання;
- способи розрахунку;
- правила додавання робіт;
- правила додавання неврахованих витрат;
- логіку групування;
- залежності між різними компонентами системи;
- типові комплектації;
- типові помилки;
- способи прийняття рішень;
- правила, за якими людина формувала фінальний кошторис.

Якщо в декількох кошторисах одна й та сама закономірність повторюється, система повинна вміти використовувати її як knowledge/rule pattern.

Якщо закономірності суперечать одна одній — НЕ вибирай випадково.
Покажи конфлікт і попроси користувача визначити правильний варіант.

9. сформувати фінальний кошторис;

==================================================
6. HUMAN-IN-THE-LOOP
==================================================

ЦЕ КРИТИЧНО ВАЖЛИВО.

AI НЕ ПОВИНЕН ВИГАДУВАТИ відсутню інформацію.

Якщо AI не може впевнено визначити:

- кількість;
- модель;
- тип товару;
- місце встановлення;
- тип системи;
- спосіб монтажу;
- параметр об'єкта;
- правило розрахунку;

він повинен:

1. визначити проблему;
2. пояснити, чого саме не вистачає;
3. сформувати коротке конкретне питання;
4. зупинити відповідну частину процесу;
5. чекати відповіді користувача;
6. після відповіді продовжити розрахунок.

НЕ треба задавати 20 питань одразу.

Об'єднуй питання, якщо це логічно.

Приклад:

"На плані є 3 входи, але в технічному завданні вказано 2. Яку кількість входів використовувати для розрахунку?"

Користувач:
"3"

AI:
оновлює аналіз → оновлює кількість → перераховує кошторис.

15. RULE ENGINE
==================================================

Правила кошторису повинні бути відокремлені від AI.

Створи rule engine / calculation layer.

Наприклад:

materials_total =
SUM(product.quantity * product.unit_price)

labor_total =
materials_total * labor_percentage

unexpected_costs =
materials_total * unexpected_percentage

grand_total =
materials_total + labor_total + unexpected_costs

АЛЕ:

НЕ ХАРДКОДЬ ці конкретні проценти як універсальні правила, якщо вони не підтверджені моїми файлами.

Правила повинні бути конфігурованими.

26. ПРОДУКТИВНІСТЬ
==================================================

Мені НЕ потрібна система, яка витрачає 15 хвилин на кожен документ через непотрібне послідовне AI-мислення.

ОПТИМІЗУЙ PIPELINE.

Ціль:

приблизно 10 хвилин або менше для великого PDF ~50–60 сторінок, якщо це реально для обраної моделі та інфраструктури.

Для цього:

- не аналізуй одне й те саме декілька разів;
- кешуй результати;
- не відправляй однаковий контент повторно;
- використовуй batch processing;
- паралельно обробляй незалежні сторінки;
- спочатку роби дешевий extraction;
- потім AI reasoning тільки там, де він потрібен;
- використовуй structured outputs;
- роби retrieval замість передачі тисяч товарів у prompt;
- використовуй deterministic calculations для математики;
- не проси LLM виконувати те, що може зробити код;
- не використовуй величезні prompts без необхідності;
- зберігай проміжні результати;
- дозволяй resume після помилки.

АЛЕ:

НЕ ЖЕРТВУЙ ТОЧНІСТЮ ТІЛЬКИ ЗАРАДИ ШВИДКОСТІ.
