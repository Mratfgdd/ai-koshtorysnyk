# AI Кошторисник

Система складання кошторисів для ландшафтних проєктів: читає комплект креслень,
формує аналіз об'єкта, підбирає позиції з вашого каталогу, рахує кількості за
правилами вашого шаблону, перевіряє результат, ставить питання там, де даних
бракує, і віддає професійний XLSX.

Правила не написані з голови — вони **скомпільовані з `Шаблон для ШІ.xlsx`**.
Доказова база: [`docs/RULES.md`](docs/RULES.md).

---

## Що всередині

```
                    ┌──────────────── детерміновано (код) ────────────────┐
PDF ──► extract ──► classify ──► [AI: сторінки] ──► object model
                                                        │
                                                        ▼
     каталог ◄── matching ◄── план кошторису ◄── [AI: план]
        │                          │
        ▼                          ▼
     ціни ────────────────► rule engine (233 правила) ──► totals ──► validation ──► XLSX
                                                                          │
                                                                          ▼
                                                                    питання користувачу
```

* **AI** відповідає лише за розуміння документів і намір: що зображено на
  кресленні, які системи потрібні, які кількості вказані.
* **Код** відповідає за всю арифметику: кількості, ціни, підсумки, перевірки.
  Модель ніколи не рахує суми.

| Шар | Технологія | Файл |
|---|---|---|
| Компілятор шаблону | openpyxl + власний парсер Excel | `app/services/ingest/formula_parser.py` |
| Rule engine | безпечний AST-евалюатор | `app/services/rules/engine.py` |
| Підсумки | детерміновані формули | `app/services/rules/totals.py` |
| Каталог | SQLite FTS5 + rapidfuzz | `app/services/catalog/search.py` |
| Документи | PyMuPDF | `app/services/docs/pdf_extract.py` |
| AI | Anthropic SDK, structured outputs, Vision | `app/services/ai/` |
| Перевірка | 14 валідаторів | `app/services/validation/validators.py` |
| Експорт | openpyxl, живі формули | `app/services/export/xlsx.py` |
| API | FastAPI + SQLAlchemy | `app/api/routes.py` |
| UI | React + Vite + TypeScript | `frontend/src/` |

## Встановлення

Потрібні **Python 3.11+** і **Node 18+**.

```bash
# 1. Залежності бекенду
cd backend
python -m pip install -r requirements.txt

# 2. Налаштування
cd ..
cp .env.example .env          # Windows: copy .env.example .env
#   впишіть ANTHROPIC_API_KEY, якщо потрібен аналіз креслень

# 3. Компіляція правил із вашого шаблону  (обов'язково)
python scripts/compile_template.py "шлях/до/Шаблон для ШІ.xlsx"

# 4. Імпорт каталогу з того самого файлу   (обов'язково)
python scripts/import_catalog.py "шлях/до/Шаблон для ШІ.xlsx"

# 5. Фронтенд
cd frontend
npm install
npm run build
```

Кроки 3 і 4 виводять звіт: скільки секцій, скільки правил, скільки позицій,
які знайдено конфлікти цін. Повторюйте їх щоразу після оновлення шаблону.

### Запуск

```bash
cd backend
python -m uvicorn app.main:app --port 8000
```

Відкрийте <http://127.0.0.1:8000> — зібраний інтерфейс віддається тим самим
процесом. Документація API: <http://127.0.0.1:8000/docs>.

Для розробки фронтенду окремо:

```bash
cd frontend && npm run dev     # http://localhost:5173, проксі на :8000
```

## Робочий процес

1. **Проєкти → Новий проєкт.** Назва, замовник, адреса, за бажанням ТЗ текстом.
2. **Завантажте PDF.** Креслення, концепцію, ТЗ. Великі комплекти (50–60 сторінок,
   150+ МБ) підтримуються. Одразу після завантаження видно розбір по сторінках:
   що це за сторінка і чи піде вона на дорогий аналіз.
3. **Аналізувати документи.** Дешеве вилучення тексту й таблиць → класифікація →
   паралельний візуальний аналіз лише тих сторінок, що несуть кількості.
4. **Аналіз об'єкта.** Площі, зони, системи, відомість рослин, покриття.
   Кожен показник має джерело, впевненість і статус
   (`підтверджено` / `припущення` / `невідомо` / `потрібне рішення`).
   Будь-яке значення можна виправити — кошторис перерахується.
5. **Сформувати кошторис.** Система відкриває потрібні секції, підставляє
   драйвери, підбирає позиції каталогу, запускає 233 правила.
6. **Проблеми та питання.** Кожна знахідка каже: що не так, чому, що зробити,
   як це вплине на суму.
7. **Редагування.** Кількість, ціна, товар, коментар. Кнопка «Чому?» показує
   правило, вхідні дані й джерела для конкретної позиції.
8. **Затвердити → Експорт.** XLSX із трьома аркушами: «Кошторис» (для замовника),
   «Обґрунтування» (аудит), «Підсумки» (формули).

## Що система робить, коли не знає

Золоте правило — **не вигадувати**.

| Ситуація | Поведінка |
|---|---|
| Товару немає в каталозі | `not_in_catalog`, ціна 0, питання користувачу |
| Кілька однаково схожих товарів | `ambiguous`, показує кандидатів з оцінками |
| Немає ціни (усі рослини) | питання «Яка ціна за 1 шт?», сума не занижується мовчки |
| Показник не читається з креслення | `UNKNOWN`, потрапляє у список невідомого |
| Дані суперечать одне одному | конфлікт із обома варіантами і питанням |
| Формулу шаблону не вдалось перекласти | `needs_review.json` з оригіналом, без здогадів |
| Немає `ANTHROPIC_API_KEY` | аналіз недоступний, решта працює; дані не підмінюються |

Помилки й відкриті питання блокують затвердження. Попередження — ні.

## Продуктивність

Ціль — до ~10 хвилин на комплект із 50–60 сторінок.

* дешеве вилучення завжди перше: 58-сторінковий растровий комплект розбирається
  за 0,4 с, 19-сторінкова концепція з векторними таблицями — за 16 с;
* титули, зміст, візуалізації, фотофіксація та маркетинг **не аналізуються**;
* сторінки обробляються паралельно (`AI_MAX_CONCURRENCY`, за замовчуванням 6);
* кожен результат кешується за хешем сторінки — повторний або відновлений
  запуск не платить двічі;
* системний промпт кешується як префікс;
* каталог **ніколи** не потрапляє у промпт — тільки retrieval;
* обчислення — детерміновані, без моделі.

## Про CRM

CRM свідомо не реалізована. Місце для неї підготовано: `CatalogItem` має
`external_id`, `price_updated_at`, `source_file` і `active`, а імпорт каталогу —
це один сервіс (`services/ingest/catalog_import.py`), який пізніше замінюється
на синхронізацію без змін у решті системи. Ціни й позиції ніде більше не
дублюються.

## Обмеження

* Аналіз документів потребує `ANTHROPIC_API_KEY`.
* Ліміт візуального аналізу — `MAX_VISION_PAGES` (40). Комплект із 58 сторінок
  обріжеться; пропущені сторінки перелічені явно, з причиною.
* SQLite за замовчуванням. Для кількох одночасних користувачів вкажіть
  `DATABASE_URL` на PostgreSQL.
* Автентифікації немає — система розрахована на запуск усередині компанії.
* Історичні кошториси парсяться у knowledge base (`HistoricalEstimate`), але
  поточна генерація спирається на правила шаблону, які точніші за статистику.
## Перевірено на живому API

Vision-гілку прогнано на `Концептуальний_проєкт_с_Будьків.pdf` (19 сторінок,
42,6 МБ) з активним ключем, модель `claude-opus-5`.

| Що перевірялось | Результат |
|---|---|
| ТЕП генплану (с. 14) | 0,047 Га / 26 / 45 / 406 м² — 4 з 4 правильно |
| Відомість покриттів (с. 15) | бордюр 147 м.п., тераса 26 м², кора 136 м², газон 259 м², плити 37 шт — правильно |
| Асортиментна відомість (с. 17) | 15 з 15 кількостей правильно, поз. 6/8/9 позначені «існуючі» |
| Сторінок проаналізовано | 17 з 19 (титул і маркетинг пропущено) |
| Час | ~5 хв на комплект, 3 виклики на зведення |

**Zero-hallucination підтверджено фактами прогону:**

* на генплані немає кількостей покриттів — модель записала це в `unreadable`,
  а не вигадала числа;
* «Площа замощення плитами» лишилась порожньою зі статусом `needs_user_input`;
* підпис «5 m2» біля тераси → `UNKNOWN` («не зрозуміло, до якого покриття»);
* знайдено **8 конфліктів** між сторінками, зокрема ТЕП «тверде покриття 45 м²»
  проти відомості (26 + 36 + плити) і крихта «31 чи 36 м²»;
* сформовано **16 питань**, згрупованих за темою;
* «Крихта сіра 36 м²» зіставлена з `Декор крихта сіра ,фр.-5-20` (кг), але
  перерахунок м²→кг **не виконано** — це питання до користувача.

### Аудит чисел

```bash
python scripts/audit.py
```

Перераховує кошторис трьома незалежними шляхами — по позиціях, через шар
підсумків і **обчислюючи живі формули з експортованого XLSX** — і падає, якщо
хоч одна цифра розійшлась більше ніж на 0,005 грн.

```
Крок 1. Арифметика позицій        53 позиції, розбіжностей 0
Крок 2. Підсумки секцій           12 перевірок
Крок 3. Підсумки кошторису         9 перевірок
Крок 4. Живі формули у XLSX        6 перевірок
Крок 5. Походження коефіцієнтів    32 обчислені кількості, усі з формули Excel
                                   233 правила, вгадано 0
РЕЗУЛЬТАТ: усі 30 перевірок пройдено, розбіжностей немає
```

Крок 5 — це доказ, що жоден коефіцієнт не вигаданий: кожна обчислена кількість
показує рядок і формулу з вашого файлу, напр.
`Анкера = 588` ← `Шаблон основний!!!! 1!D719  =D718*4`.

## Вигляд експорту

Стилістика взята з вашої ж пропозиції
«КП 2026 (1 Квартал) Максим Скленар ПМ - КП Галина Будьків.pdf»:

| Елемент | Джерело |
|---|---|
| Зелений банер і шапки таблиць | `#6AA84F` — піксельна проба з вашого PDF |
| Смуга-маркер секції | `#CFE2F3` |
| Смуга назви секції | `#E2EFD9` |
| Логотип GARDENER | витягнутий з вашого PDF → `backend/app/data/brand/logo.png` |
| Шапка | Замовник, Адреса об'єкту, Дата рахунку, Пропозиція дійсна протягом |
| Колонки | `# / Матеріали / К-сть / Од. вим. / Ціна / Сума` |
| Підсумки | «Разом за матеріали», «Разом за роботу», «Разом <Секція>», «Загальний рахунок», «Аванс (на матеріали)», «Аванс (на роботи)», «Залишок» |
| Формат чисел | бухгалтерський, `1 100,00`, прочерк для нуля |

Секції йдуть блоками (Підготовчий етап, Рахунок Доріжка, Рахунок Озеленення,
Рахунок Газон…), суми — живі формули Excel, а не «запечені» числа.
Аркуш гортається та друкується як єдиний документ: без закріплених областей
і без повтору шапки на кожній сторінці. Сітка увімкнена, нулі — «—».

## Деплой

Покроково: [`docs/DEPLOY.md`](docs/DEPLOY.md) — Render (бекенд) + Vercel (фронтенд),
обидва безкоштовні, ~3 хвилини.

* `render.yaml` — готовий Blueprint: `--host 0.0.0.0 --port $PORT`, health-check,
  диск 1 ГБ під базу й завантаження, ключ як secret.
* `frontend/vercel.json` — SPA-rewrites і кеш статики.
* `VITE_API_BASE_URL` — адреса бекенду для фронтенду на Vercel.
* CORS дозволяє будь-який `*.vercel.app` плюс домени з `CORS_ORIGINS`.
* `backend/app/data/seed/catalog.json` — прайс їде разом із кодом, тому свіжий
  інстанс піднімається з готовими 844 позиціями. Оновлюється
  `python scripts/make_seed.py`.
